# Image Attachments for Notes & Comments — Implementation Plan

## Goal

Allow users to attach **multiple images** to a single `Note` **or** a
single `Comment`. Original full-resolution files live in a dedicated
GCS bucket; a separate bucket is reserved for thumbnails that will be
generated by an asynchronous process introduced in a later iteration.

The first iteration ships:

- A generic `Image` model with nullable FKs to both `Note` and
  `Comment`, indexed for fast relational lookups.
- A REST upload endpoint that streams the file to GCS and creates the
  DB row in a single request.
- Terraform for the originals bucket and the (currently empty)
  thumbnails bucket, with IAM scaffolded so a future Cloud Function /
  Pub/Sub-triggered worker can write thumbnails without further IAM
  changes.

## Non-goals (this iteration)

- Synchronous or asynchronous thumbnail generation.
- Image moderation / virus scanning.
- Re-encoding, EXIF stripping, format conversion.
- CDN configuration beyond what GCS provides by default.
- Editing images in place (replace = delete + new upload).

## 1. Django Model

File: `@/Users/tedis.rozenfelds/personal_data/p_projects/Bible Research/bible_research/annotations/models.py`

Add alongside the existing `Note` and `Comment` models. The codebase
convention is a **string PK with a short prefix + 15 hex chars** (see
`generate_note_id`, `generate_comment_id`, `generate_tag_id`). The
spec asks for `IMG_4432`-style IDs; we follow the project convention
and use `IMG_` + 13 hex chars to stay within the existing 18-char
`max_length`.

```python
def generate_image_id():
    return f"IMG_{str(uuid.uuid4()).upper().replace('-', '')[:13]}"


class Image(models.Model):
    """
    Generic image attachment. Belongs to *either* a Note or a Comment
    (XOR — enforced by a CheckConstraint). The file itself lives in
    GCS; only the storage URL is persisted here.

    Indexing strategy:
      - comment_id and note_id each carry Django's default
        db_index=True, made explicit in Meta.indexes for documentation
        and so future composite indexes have a clear home.
    """

    id = models.CharField(
        max_length=18,
        default=generate_image_id,
        primary_key=True,
        editable=False,
        help_text="Unique identifier for the image (IMG_…).",
    )
    storage_url = models.URLField(
        max_length=1024,
        help_text=(
            "Canonical GCS URI of the original full-resolution file "
            "(e.g. gs://<bucket>/originals/<image_id>/<filename>)."
        ),
    )
    content_type = models.CharField(
        max_length=64,
        blank=True,
        help_text="MIME type captured at upload time (e.g. image/jpeg).",
    )
    size_bytes = models.PositiveIntegerField(
        null=True, blank=True,
        help_text="File size in bytes, captured at upload time.",
    )
    comment = models.ForeignKey(
        Comment,
        on_delete=models.CASCADE,
        null=True,
        blank=True,
        related_name="images",
        help_text="Comment this image is attached to (nullable).",
    )
    note = models.ForeignKey(
        Note,
        on_delete=models.CASCADE,
        null=True,
        blank=True,
        related_name="images",
        help_text="Note this image is attached to (nullable).",
    )
    uploaded_by = models.ForeignKey(
        User,
        on_delete=models.SET_NULL,
        null=True,
        blank=True,
        related_name="uploaded_images",
        help_text="User who uploaded the image.",
    )
    created_at = models.DateTimeField(auto_now_add=True)

    class Meta:
        verbose_name = "Image"
        verbose_name_plural = "Images"
        ordering = ["-created_at"]
        indexes = [
            models.Index(fields=["comment_id"], name="image_comment_id_idx"),
            models.Index(fields=["note_id"], name="image_note_id_idx"),
        ]
        constraints = [
            # XOR: exactly one of (comment, note) must be set.
            models.CheckConstraint(
                name="image_exactly_one_parent",
                check=(
                    Q(comment__isnull=False, note__isnull=True)
                    | Q(comment__isnull=True, note__isnull=False)
                ),
            ),
        ]
```

### Migration

`python manage.py makemigrations annotations -n add_image_model`
followed by `migrate`. No data backfill required.

### Admin

Register a minimal `ImageAdmin` in `annotations/admin.py` for

## 2. Backend Upload Logic

### Endpoint shape

Follow the existing nested-router style in
`@/Users/tedis.rozenfelds/personal_data/p_projects/Bible Research/bible_research/annotations/urls.py`.
Two thin endpoints rather than one polymorphic one — clearer auth
boundaries, simpler permission checks, no ambiguous payloads:

```
POST /api/v1/notes/{note_pk}/images/
POST /api/v1/notes/{note_pk}/comments/{comment_pk}/images/
GET  /api/v1/notes/{note_pk}/images/
GET  /api/v1/notes/{note_pk}/comments/{comment_pk}/images/
DELETE /api/v1/images/{image_pk}/
```

Request: `multipart/form-data` with a single `file` field.
Response: serialized `Image` row including a short-lived **signed GET
URL** (mirrors how audio is served — see `signed_audio_url` in
`@/Users/tedis.rozenfelds/personal_data/p_projects/Bible Research/bible_research/bible/services/storage/gcs.py:162`)
so clients never read directly from a public bucket.

### Permission rules

- Upload to a `Note`: requester must be the note's owner.
- Upload to a `Comment`: requester must be the comment's author.
- Read: same visibility scope as
  `get_accessible_notes_qs` in
  `@/Users/tedis.rozenfelds/personal_data/p_projects/Bible Research/bible_research/annotations/views.py:29`.
- Delete: only the uploader (or the parent owner) may delete.

### File-naming convention (future-proofing hook for thumbnails)

This is the contract a future Cloud Function / Pub/Sub worker will
rely on. **Do not deviate** without updating this plan.

Originals bucket layout:

```
originals/<image_id>/source<ext>
```

- `<image_id>` is the DB primary key (`IMG_…`). Putting it in the
  path means the worker recovers the row id from the object name
  without a sidecar metadata read.
- `source<ext>` keeps the extension for content-type inference and
  guarantees a single, predictable object per image.

Thumbnails bucket layout (reserved, written later):

```
thumbnails/<image_id>/<size>.webp
```

Where `<size>` is one of `sm | md | lg`. The worker will:

1. Receive a GCS Pub/Sub `OBJECT_FINALIZE` event for
   `originals/<image_id>/source*`.
2. Parse `<image_id>` from the object name.
3. Generate sized variants and write to the thumbnails bucket using
   the path above.
4. Optionally PATCH a future `Image.thumbnails_ready` flag (out of
   scope here — model leaves room for a later additive migration).

### Upload service module

New file:
`bible_research/annotations/services/image_storage.py`

Following the layout of
`@/Users/tedis.rozenfelds/personal_data/p_projects/Bible Research/bible_research/bible/services/storage/gcs.py`.
Responsibilities:

- `upload_original(image_id, django_uploaded_file) -> (gs_uri, size, content_type)`
  - Streams via `blob.upload_from_file` (no in-memory copy of large
    files).
  - Sets `content_type` from the upload, sanitises the extension
    against an allowlist (`.jpg/.jpeg/.png/.webp/.gif`), rejects
    everything else with 415.
  - Enforces a configurable `IMAGE_MAX_BYTES` (default 10 MiB).
- `signed_image_url(image_id, ttl_seconds=...)` — V4 signed GET, IAM
  signBlob path, mirrors `signed_audio_url`.
- `delete_original(image_id)` — best-effort delete; tolerated 404.

### View / serializer wiring

- `ImageSerializer` exposes: `id, storage_url (gs://…), signed_url
  (computed), content_type, size_bytes, comment, note, uploaded_by,
  created_at`.
- `NoteImageViewSet` and `CommentImageViewSet` (DRF
  `ModelViewSet`-ish, but `update` disabled). `perform_create`:
  1. Validate parent ownership.
  2. Generate an `Image` row with the prefixed PK (PK known **before**
     upload so it can be embedded in the object path).
  3. Call `upload_original`.
  4. Save `storage_url`, `size_bytes`, `content_type`.
  5. If GCS upload fails after the row is created, delete the row in
     a `try/except` (transaction-safe via
     `transaction.on_commit`-style guard, or simpler: create row only
     after GCS write succeeds — preferred, since DB is the cheap
     side).
- Honour the project's existing logging style (`logger.info` /
  `logger.exception`).

- XOR constraint: payload with both parents set → 400.
- Permission: non-owner upload → 403.

## 3. Terraform

New file:
`bible_research/terraform/images_storage.tf`

Mirrors `audio_storage.tf` for consistency.

```hcl
# Originals: full-resolution user-uploaded images. App Engine runtime
# writes; thumbnail worker reads.
resource "google_storage_bucket" "images_originals" {
  name                        = "${var.project_id}-images-originals"
  location                    = local.app_engine_region
  project                     = var.project_id
  force_destroy               = false
  uniform_bucket_level_access = true

  versioning { enabled = true }

  lifecycle_rule {
    condition { with_state = "ARCHIVED", age = 30 }
    action    { type = "Delete" }
  }
  lifecycle_rule {
    condition { age = 7 }
    action    { type = "AbortIncompleteMultipartUpload" }
  }
}

# Thumbnails: written later by an async worker. Empty in this
# iteration, but provisioned now so IAM is in place.
resource "google_storage_bucket" "images_thumbnails" {
  name                        = "${var.project_id}-images-thumbnails"
  location                    = local.app_engine_region
  project                     = var.project_id
  force_destroy               = false
  uniform_bucket_level_access = true

  lifecycle_rule {
    condition { age = 7 }
    action    { type = "AbortIncompleteMultipartUpload" }
  }
}

# App Engine runtime — write originals, read thumbnails (to sign URLs
# for clients).
resource "google_storage_bucket_iam_member" "appspot_originals_admin" {
  bucket = google_storage_bucket.images_originals.name
  role   = "roles/storage.objectAdmin"
  member = "serviceAccount:${local.appspot_email}"
}
resource "google_storage_bucket_iam_member" "appspot_thumbnails_reader" {
  bucket = google_storage_bucket.images_thumbnails.name
  role   = "roles/storage.objectViewer"
  member = "serviceAccount:${local.appspot_email}"
}

# Future thumbnail worker — service account created now so IAM
# bindings already exist when the Cloud Function lands. No deploy
# follows from this alone; the worker is a later PR.
resource "google_service_account" "thumbnail_worker" {
  account_id   = "thumbnail-worker"
  display_name = "thumbnail-worker"
  description  = "Async worker that generates image thumbnails."
  project      = var.project_id

  depends_on = [google_project_service.enabled]
}

resource "google_storage_bucket_iam_member" "thumbnail_worker_originals_reader" {
  bucket = google_storage_bucket.images_originals.name
  role   = "roles/storage.objectViewer"
  member = "serviceAccount:${google_service_account.thumbnail_worker.email}"
}
resource "google_storage_bucket_iam_member" "thumbnail_worker_thumbnails_admin" {
  bucket = google_storage_bucket.images_thumbnails.name
  role   = "roles/storage.objectAdmin"
  member = "serviceAccount:${google_service_account.thumbnail_worker.email}"
}
```

Notes:

- Add `thumbnail-worker@…` to the `serviceAccountAdmin` condition

- Outputs: expose both bucket names from `outputs.tf` so the

- The thumbnails bucket intentionally has **no** versioning — the

## Execution order

1. Terraform PR: provision both buckets + IAM. Apply before merging
   any app code so the runtime SA has write access on first deploy.
2. Backend PR:
   - `Image` model + migration.
   - `image_storage` service.
   - Viewsets, serializer, URL routes.
   - Settings + `.env.example`.
   - Tests (mocked GCS).
3. Frontend / client PR (out of scope here): upload UI consuming the
   new endpoints.
4. Later PR: thumbnail Cloud Function triggered by
   `OBJECT_FINALIZE` on the originals bucket, writing to the
   thumbnails bucket using the path contract above.

## Risks & open questions

- **Direct-to-GCS uploads via signed URL** would be cheaper at scale
  than proxying through App Engine. Deferred — App Engine proxy is
  simpler and matches existing patterns; revisit if upload traffic
  becomes meaningful.
- **Quota / abuse**: no per-user upload rate limit in this
  iteration. Track in a follow-up if needed.
- **Soft delete**: comments use `is_deleted`; images use hard delete
  + GCS delete. If we ever want undo, add `is_deleted` and skip the
  GCS delete until a janitor sweeps.
